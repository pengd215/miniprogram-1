## 二、云函数逻辑/安全修复

| # | 云函数 | 原问题 | 修复方式 |
|---|--------|--------|----------|
| 1 | userLogin | **致命**：密码明文存储并直接在 where 条件中比对；无参调用时不返回 openid | 改为 sha256(盐+密码) 哈希存储；先按 username 查再比对密码；存量明文账号登录成功自动迁移为哈希；新增无参模式返回当前 openid（兼容 app.js 与设置页） |
| 2 | userLogin | 参数未校验可能返回意外结果 | 增加 username 类型与空值校验 |
| 3 | userLogin | 向客户端返回 `_openid`（敏感） | 返回值中移除 |
| 4 | getFlowList | **严重**：oe_no/type/dateStr 三个筛选条件互相覆盖，组合查询失效 | 重构为 conditions 数组 + `_.and()` 统一组合 |
| 5 | getFlowList / checkPart / clientSearchQuote | 正则注入（ReDoS）：用户输入直接进 RegExp | 增加 `escapeRegExp` 转义 |
| 6 | clientSearchQuote | 生产代码保留调试日志（打印完整数据） | 移除"第一条数据"调试日志 |
| 7 | generateQRCode | `cloud.init()` 未传 env，多环境可能连错库 | 补 `env: cloud.DYNAMIC_CURRENT_ENV`；增加 size 上限 1000 |
| 8 | getProductById | 文档不存在时 404 分支不可达（SDK 抛异常），错误时把 Error 对象透传前端 | catch 中识别"不存在"返回 404；失败响应不再含 err 对象 |
| 9 | submitInbound | `parseInt` 缺 radix；`model` 字段信任前端注入 | `parseInt(quantity, 10)`；model 仅取数据库字段 |
| 10 | submitOutbound | `parseInt` 缺 radix | `parseInt(quantity, 10)` |
| 11 | managePermission | 无"至少保留一名管理员"保护，唯一 admin 可将自己降级导致系统锁死 | 降级 admin 前检查其他 admin 数量 |
| 12 | warehouseManage | generateLocations 先删旧库位再建新库位，中途失败数据丢失；500 条并发写入触发限流 | 改为先建后删；分批串行写入（50 条/批） |
| 13 | 全部云函数 package.json | 7 个用 `wx-server-sdk: latest`（版本漂移）；userLogin name 错为 `use`；getProductById name 截断为 `getProductBy` | 统一锁定 `~4.0.2`；修正两个 name |
